# Data Dictionary

All data in this folder is **100% synthetic**: invented patient/provider names,
invented towns, no real PHI, and no affiliation with any real practice. It is
generated by `generate_data.py` (fixed seed = 42) and is committed to the repo
so the project runs without regenerating anything. To regenerate:

```
.venv\Scripts\python.exe data\generate_data.py
.venv\Scripts\python.exe data\validate_data.py
```

Data window: **2025-03-01 to 2026-08-31** (18 months). All appointment and
surgery dates fall on weekdays within this window; `scheduled_date` and
referral `completion_date` may fall slightly outside it (a booking made
before the window, or a referral completed a few weeks after the window
closes) — this is intentional and mirrors real scheduling lag.

This dataset intentionally contains a small, documented set of data-quality
defects (missing fields, orphaned foreign keys, duplicate IDs) so the Phase 2
Data Quality endpoints have something real to report. The exact injected
counts are ground-truthed in [`data_quality_injected.md`](data_quality_injected.md).

## offices.csv (15 rows)

| Column | Type | Notes |
|---|---|---|
| `office_id` | string | PK, `OFF001`–`OFF015` |
| `office_name` | string | Invented town + "Orthopaedic Center" |
| `region` | string | `Philadelphia Metro` (6 offices), `South Jersey` (5), `Central Florida` (4) |
| `state` | string | `PA`, `NJ`, `FL` |
| `has_onsite_imaging` | bool | ~60% true |
| `has_onsite_pt` | bool | ~55% true; correlated with, but independent of, imaging |

## providers.csv (60 rows)

| Column | Type | Notes |
|---|---|---|
| `provider_id` | string | PK, `PRV001`–`PRV060` |
| `provider_name` | string | Synthetic `Dr. First Last` |
| `subspecialty` | string | Hip & Knee, Spine, Sports Medicine, Hand & Wrist, Foot & Ankle, Physical Medicine & Rehab, Pain Medicine, Oncology |
| `primary_office_id` | string | FK → offices; every office has ≥2 providers |
| `hire_date` | date | ~52 providers hired 1–15 years before the window; 8 hired *during* the window (ramping volume) |
| `is_surgeon` | bool | False only for Physical Medicine & Rehab and Pain Medicine |

## patients.csv (5,000 rows)

| Column | Type | Notes |
|---|---|---|
| `patient_id` | string | PK, `PAT00001`–`PAT05000` |
| `date_of_birth` | date | Age skewed older (mean ~58, ortho population), clipped 18–95 |
| `gender` | string | `F` / `M` / `Other` (~49/49/2%) |
| `insurance_type` | string | Commercial, Medicare, Medicaid, Self-Pay — Medicare share rises sharply for age 65+ |
| `home_zip` | string | 5-digit, region-consistent prefix; **contains injected nulls** |

## appointments.csv (~25,000 rows + 12 injected duplicates)

| Column | Type | Notes |
|---|---|---|
| `appointment_id` | string | PK, `APT000001`– ; **contains 12 injected duplicate IDs** |
| `patient_id` | string | FK → patients |
| `provider_id` | string | FK → providers; **contains 15 injected orphaned values (`PRV999`)** |
| `office_id` | string | FK → offices; ~90% the provider's primary office, else another office in the same region |
| `scheduled_date` | date | When the booking was made |
| `appointment_date` | date | The actual visit date (weekdays only, seasonally weighted) |
| `appointment_type` | string | `New Patient` (first visit with that specific provider) or `Follow-Up`; **contains injected nulls** |
| `status` | string | `Completed`, `No-Show`, `Cancelled`, `Rescheduled` |
| `lead_time_days` | int | `appointment_date - scheduled_date`; drivers: subspecialty demand, +8% drift over the window |

**No-show rate definition:** `No-Show ÷ (Completed + No-Show)` — cancellations
and reschedules are excluded from the denominator (standard ambulatory
definition). Overall ~14%, higher for Medicaid/Self-Pay and on Mondays.

## surgeries.csv (3,000 rows)

| Column | Type | Notes |
|---|---|---|
| `surgery_id` | string | PK, `SRG0001`– |
| `patient_id` | string | FK → patients (drawn from a prior completed visit) |
| `provider_id` | string | FK → providers; surgeons only |
| `surgery_date` | date | 14–60 days after the qualifying completed visit |
| `procedure_type` | string | Drawn from a per-subspecialty procedure menu |
| `subspecialty` | string | Matches the operating provider |
| `office_id` | string | Provider's primary office (site of surgery) |
| `is_outpatient` | bool | ~72% overall; ~95% for arthroscopy/release procedures, ~25% for fusions |

## ancillary_referrals.csv (~4,000 rows + 5 injected duplicates)

| Column | Type | Notes |
|---|---|---|
| `referral_id` | string | PK, `REF0001`– ; **contains 5 injected duplicate IDs** |
| `patient_id` | string | FK → patients; **contains 8 injected orphaned values (`PAT99999`)** |
| `referring_provider_id` | string | FK → providers |
| `service_type` | string | Physical Therapy (45%), Imaging (30%), Orthotics (13%), Hand Therapy (12%) |
| `referral_date` | date | Tied to a real appointment date for that patient |
| `completed` | bool | Base completion rate by service type, reduced when the referring office lacks the matching onsite service (leakage effect) |
| `completion_date` | date, nullable | 3–45 days after `referral_date` when completed; **contains injected nulls where `completed=True`** |
| `office_id` | string | FK → offices |

**Leakage effect:** PT and Imaging referrals sent to an office without the
matching `has_onsite_pt` / `has_onsite_imaging` flag complete at a
meaningfully lower rate (~70% vs ~83%) — this is the signal the Phase 2
`/api/ancillary/leakage` endpoint is meant to surface.
